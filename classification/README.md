# classification/

Powertrain classification from the model designation, where the registry
records don't say it. Two users, one format, separate files:

- **Argentina** (DNRPA) — records carry **no fuel field**, so the gallery
  derives BEV / PHEV / EREV / HEV / MHEV / ICE from the designation.
  Full method, decision log and runbook: [docs/architecture/39-source-argentina.md](../docs/architecture/39-source-argentina.md) §4–§7.
- **Ecuador** (SRI) — the fuel is known, but SRI has **one hybrid code**; only
  hybrids reach the rules, which split off PHEV / EREV (default: HEV).
  Method, rule hits and the ZEMO / AEADE check: [docs/architecture/48-source-ecuador.md](../docs/architecture/48-source-ecuador.md) §3b.

| file | edited by | what it is |
|---|---|---|
| `argentina_rules.csv` | **hand** — the classifier's source of truth | ordered first-match rules: `order, id, class, brand, pattern, kind, reason, evidence, example_brand, example_model` |
| `argentina_models.csv` | generated by `scripts/fetch_argentina.py` | every designation registered in scope → `class`, deciding `rule`, units, first/last seen. Its git diff is the audit trail |
| `argentina_top.json` | generated by `scripts/fetch_argentina.py` | top brands / designations per class, last 12 months (country-neutral schema, doc 39 §5.3) |

Changing a rule: edit `argentina_rules.csv` (keep `order` 1..N; add a real
example), run `python scripts/test_fetch_argentina.py`, commit, then dispatch
**Fetch Argentina data (DNRPA)** with `force = true` so the full history is
re-classified. Never hand-edit the two generated files.

The public source page (`sources/argentina.html`) renders all three.

**Ecuador:**

| file | edited by | what it is |
|---|---|---|
| `ecuador_rules.csv` | **hand** — the classifier's source of truth | same columns as Argentina's; classes `PHEV` / `EREV` only (anything unmatched stays `HEV`, rule `default-hev`). `load_rules()` refuses the file unless every rule has a reason, evidence and a real example that its own rule decides |
| `ecuador_models.csv` | generated by `scripts/fetch_ecuador.py` | every hybrid designation → `class`, deciding `rule`, units — one row per brand, designation, scope and **year** (a normal run replaces the years it re-derives and re-classifies the older ones with the current rules) |

Changing a rule: edit `ecuador_rules.csv`, run `python scripts/test_fetch_ecuador.py`,
commit, then dispatch **Fetch Ecuador data** with `backfill = true` so the CSVs'
full history follows. The top list lives in `market/ecuador_top.json`; the
source page (`sources/ecuador.html#classification`) renders rules and mapping.
